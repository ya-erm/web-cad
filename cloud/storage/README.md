# Облачная библиотека

Файлы загружаются напрямую браузером в приватный S3, не проходят через Cloud Functions.
Функция проверяет сессию, подписывает адреса и публикует небольшую запись метаданных.
Работа библиотеки не требует постоянно работающей ВМ.

## Ресурсы и ограничения

- YDB `webcad-db`: таблицы `cloud_folders`, `cloud_documents`, `cloud_uploads`,
  схема `../api/cloud-schema.sql`. Все ключи начинаются с `user_id`.
- S3 `webcad-documents`: существующий лимит 10 ГиБ, анонимный доступ выключен,
  версия объектов не включена. Проекты gzip до 20 МиБ, миниатюры до 1 МиБ.
- Аккаунт подписи `webcad-storage`: `ajeabdl1re6q61l4k6c0`, IAM storage.uploader
  только на бакете. В политике добавлены необходимые доступы к uploads/ и documents/,
  существующие разрешения API и deployer сохранены.
- Ключи подписи находятся в обычных переменных окружения версии функции
  `STORAGE_ACCESS_KEY_ID` и `STORAGE_SECRET_ACCESS_KEY` по решению владельца.
  Lockbox удалён; значения не включены в исходники и ZIP и не выводятся при деплое.
- Временные PUT/GET адреса на точные ключи действуют 10 минут. Получивший адрес
  может выполнить указанную операцию до истечения срока; адреса нельзя логировать.
- CORS: только `https://cad.ya-erm.ru`, GET/PUT/HEAD, Content-Type/x-amz-*,
  expose ETag/Content-Length, maxAge 600 секунд.
- Загрузки в YDB: TTL 24 часа по expires_at с явной проверкой в обработчике.
- Правило `webcad-upload-cleanup`: только prefix uploads/, удаление через 3 дня.
  Готовые documents/ этим правилом не затрагиваются.

## Публикация снимка

1. `/cloud/prepare` проверяет владельца, папку, размеры, ожидаемую ревизию.
   Сохраняет попытку и выдаёт короткие PUT-адреса в uploads/<user>/<doc>/<upload>/.
2. Браузер загружает проект и миниатюру. Content-Length входит в подпись.
3. `/cloud/commit` проверяет фактические размеры через HEAD и копирует объекты
   в documents/<user>/<doc>/<revision>/. Повторное использование PUT-адреса
   не может изменить опубликованный снимок. CopySourceIfMatch привязывает копию
   к проверенному объекту.
4. Только затем транзакция YDB меняет текущую ревизию с проверкой ожидаемой ревизии и времени изменения метаданных.
   Повторный commit идемпотентен. При конфликте текущая запись не меняется.
5. `/cloud/list` возвращает метаданные и короткие GET-адреса миниатюр.
   `/cloud/open` подписывает скачивание выбранного документа; браузер проверяет
   SHA-256 архива и ограничивает распаковку 100 МиБ.

Все изменяющие запросы проверяют Origin приложения, сессии — HttpOnly cookie.
Ключ пользователя берётся из действующей сессии, а не из тела запроса.
Сессия не предоставляет пользователю IAM-прав или постоянного ключа S3.
Папки не зависят от путей объектов: переименование и перемещение меняют метаданные.

## Фоновая очередь и хранение снимков

Автосинхронизация включается настройкой браузера (по умолчанию включена),
требует подтверждённого аккаунта, сети и видимой вкладки. Пауза после правок —
30 секунд, минимум между загрузками одного документа — 60 секунд, общая пауза —
15 секунд. Непрерывные правки не откладывают попытку дольше 120 секунд;
ошибки повторяются с задержкой до 5 минут. Единую полосу загрузки делят ручные
и фоновые отправки через Web Locks или транзакционную аренду IndexedDB.

Очередь восстанавливается из summary документа. Снимок модели, именованных версий
и их часов изменения читается атомарно. Подтверждение помечает только этот снимок;
новые правки остаются грязными. Сохранённая попытка позволяет восстановить commit
после потери ответа. Смена аккаунта прерывает фоновые запросы и проверяется
`expectedUserId` на сервере. Несколько разных локальных вариантов и конфликт
исходной ревизии требуют явного выбора пользователя.

Список метаданных проверяется не чаще раза в минуту; обновления передаются UI без
дополнительного LIST, адрес миниатюры сохраняется до 8 минут. Это запрос к YDB,
а не перечисление S3. Чистый закрытый кеш обновляется атомарно; открытая модель
получает уведомление вместо незаметной замены.

Именованные версии и ветки пока входят в каждый загружаемый проект,
автоматическая история и 3D-кеш исключены. Облачная корзина меняет метаданные;
окончательного удаления пользовательских документов пока нет.

Метаданные `retired` учитывают заменённые технические снимки. Текущий и последний
предыдущий сохраняются, более старые допускают очистку через 10 минут: до двух
ревизий за запрос, без S3 LIST, с повторной проверкой актуальной записи. Ошибки
очистки сохраняют метаданные. При 32 старых снимках автоматическая подготовка
останавливается кодом 429. Для удаления требуется отдельно согласованное право
API `s3:DeleteObject` в `documents/*` и базовая роль `storage.editor` только на этот бакет. Оба разрешения согласованы владельцем; политика ограничивает доступ прежними чтением/записью/списком и удалением в `documents/*`. Привязку роли задают по `resourceId` из свежего GET бакета, а политику — по имени.

Ранее накопленные объекты без `retired`, а также объекты после неудачной публикации
пока требуют отдельной сборки мусора. Текущие документы удалять по возрасту нельзя.
Папки компьютера в автоматическую очередь не входят.

## Единая библиотека

«Мои документы» объединяет локальный и облачный экземпляры по известному ID,
а не по совпадению имени. Связь хранится в DocumentSummary.cloudSource:
userId/documentId/revision/cloudModified и локальные отметки savedModified,
savedVersionsModified, savedName, savedFolderId.
Первая загрузка сохраняет эту связь, первое скачивание сохраняет общий ID через
атомарную addDocumentIfAbsent. При занятости ID изменённые локальные данные не
перезаписываются: варианты группируются одной карточкой и остаются доступными.
Папки сопоставляются по сохранённой cloudSource, ID либо однозначному пути.
Их метаданные отражаются локально без удаления имеющихся папок и моделей.
Файлы компьютера остаются отдельными; перенос в библиотеку выполняется явной копией.

Владелец бакета aje8slr6l74vhbrn6s3q имеет IAM storage.admin/editor и точечные
Allow s3:GetObject на объекты, s3:ListBucket/s3:GetBucketLocation на бакет.
Публичные флаги выключены. Это исправляет скачивание через консоль без открытия
доступа анонимным пользователям; проверено по предоставленной ссылке (HTTP 200).
