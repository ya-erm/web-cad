# Облачная библиотека: первый этап

Файлы загружаются напрямую браузером в приватный S3, не проходят через Cloud Functions.
Функция проверяет сессию, подписывает адреса и публикует небольшую запись метаданных.
Работа библиотеки не требует постоянно работающей ВМ.

## Ресурсы и ограничения

- YDB `webcad-db`: таблицы `cloud_folders`, `cloud_documents`, `cloud_uploads`,
  схема `../api/cloud-schema.sql`. Все ключи начинаются с `user_id`.
- S3 `webcad-documents`: существующий лимит 10 ГиБ, анонимный доступ выключен,
  версия объектов не включена. Проекты gzip до 20 МиБ, миниатюры до 1 МиБ.
- Аккаунт подписи `webcad-storage`: `ajeabdl1re6q61l4k6c0`, IAM storage.uploader
  только на бакете. В политике добавлены необходимые доступы к uploads/ и documents/,
  существующие разрешения API и deployer сохранены.
- Lockbox `webcad-storage-signing`: `e6q0p6ep8qvrgi326cbk`, версия
  `e6q10nc8q7u5v7jlcdep`, ключи `access_key_id`, `secret_access_key`.
  payloadViewer только у `webcad-api`; значения не включены в исходники и ZIP.
- Временные PUT/GET адреса на точные ключи действуют 10 минут. Получивший адрес
  может выполнить указанную операцию до истечения срока; адреса нельзя логировать.
- CORS: только `https://cad.ya-erm.ru`, GET/PUT/HEAD, Content-Type/x-amz-*,
  expose ETag/Content-Length, maxAge 600 секунд.
- Загрузки в YDB: TTL 24 часа по expires_at с явной проверкой в обработчике.
- Правило `webcad-upload-cleanup`: только prefix uploads/, удаление через 3 дня.
  Готовые documents/ этим правилом не затрагиваются.

## Публикация снимка

1. `/cloud/prepare` проверяет владельца, папку, размеры, ожидаемую ревизию.
   Сохраняет попытку и выдаёт короткие PUT-адреса в uploads/<user>/<doc>/<upload>/.
2. Браузер загружает проект и миниатюру. Content-Length входит в подпись.
3. `/cloud/commit` проверяет фактические размеры через HEAD и копирует объекты
   в documents/<user>/<doc>/<revision>/. Повторное использование PUT-адреса
   не может изменить опубликованный снимок. CopySourceIfMatch привязывает копию
   к проверенному объекту.
4. Только затем транзакция YDB меняет текущую ревизию с проверкой ожидаемой.
   Повторный commit идемпотентен. При конфликте текущая запись не меняется.
5. `/cloud/list` возвращает метаданные и короткие GET-адреса миниатюр.
   `/cloud/open` подписывает скачивание выбранного документа; браузер проверяет
   SHA-256 архива и ограничивает распаковку 100 МиБ.

Все изменяющие запросы проверяют Origin приложения, сессии — HttpOnly cookie.
Ключ пользователя берётся из действующей сессии, а не из тела запроса.
Сессия не предоставляет пользователю IAM-прав или постоянного ключа S3.
Папки не зависят от путей объектов: переименование и перемещение меняют метаданные.

## Ограничения этого этапа

Загрузка явная, автоматической отправки правок нет. Повторное добавление того же
ID даёт конфликт; интерфейс предлагает отдельную копию. Новая ревизия не заменяет
изменённые локальные данные. Именованные версии и ветки пока входят в каждый
загружаемый проект, автоматическая история и 3D-кеш исключены.
Непрерывная синхронизация, облачная корзина и политика хранения старых постоянных
снимков ещё не включены. Объекты незавершённых попыток в documents/ после ошибки
публикации пока требуют отдельной будущей сборки мусора; текущие документы удалять
по возрасту нельзя. До включения автоматической синхронизации согласовать хранение
и реализовать очистку таких объектов.
