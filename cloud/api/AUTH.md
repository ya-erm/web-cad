# Авторизация WebCAD

Обработчики опубликованы 18 ноября 2026 на `https://api.cad.ya-erm.ru`.
Таблицы `auth_users`, `auth_identities`, `auth_sessions`, `auth_requests` созданы
в `webcad-db` по `auth-schema.sql`. Интерфейс содержит вход, профиль и выход;
сохранение документов в облако пока не реализовано.

Первый провайдер — Яндекс ID. Пользователь WebCAD имеет собственный `user_id`,
к которому привязываются внешние учётные записи. Это оставляет возможность
добавить Google, GitHub и passkey. Аккаунты не объединяются автоматически по email.

## Регистрация OAuth-приложения

В [Яндекс OAuth](https://oauth.yandex.ru/) создать приложение типа
«Для авторизации пользователей», веб-сервис:

- название: WebCAD;
- сайт: `https://cad.ya-erm.ru`;
- Redirect URI: `https://api.cad.ya-erm.ru/auth/yandex/callback`;
- права: `login:info`, `login:email`.
- по согласованию добавлен портрет: `login:avatar`.

Транспорт OAuth подготовлен в `yandex.mjs`: PKCE S256, обмен кода на сервере,
получение минимального профиля с портретом. Есть тесты с имитацией ответов Яндекса.
Проверка state и браузерной cookie, одноразовое потребление попытки, транзакции
YDB и сессии подключены к обработчику.

OAuth-приложение зарегистрировано пользователем. Client ID и Client Secret
помещены в Yandex Lockbox `webcad-oauth` (`e6qju6g6ec8o8d9brp8n`), версия
`e6qnv4jri518m60pmi1b`, ключи `client_id` и `client_secret`.
Секреты не включены в репозиторий или архив функции. Версия функции получает их через интеграцию Cloud Functions с Lockbox.

## Поток входа

1. `GET /auth/yandex/start` создаёт одноразовую попытку входа, случайный state,
   PKCE S256 и связь с браузером через защищённую cookie на домене API.
2. Яндекс возвращает code и state на точный Redirect URI. Сервер проверяет
   браузерную связь, срок жизни и однократность попытки, обменивает код на токен
   и получает стабильный ID пользователя Яндекса.
3. Сервер транзакционно находит или создаёт внутренний аккаунт и сессию;
   возвращает случайный секрет сессии в cookie `HttpOnly; Secure; SameSite=Lax`
   с областью только API (без `Domain=.ya-erm.ru`). В БД хранится хеш секрета.
4. Сервер перенаправляет браузер на заранее определённый адрес WebCAD,
   без OAuth-кода, токена и секрета сессии в URL. Произвольный return URL не принимается.
5. `GET /auth/session` возвращает минимальный профиль; `POST /auth/logout`
   отзывает текущую сессию и удаляет cookie.

Выход проверяет Origin для защиты от CSRF. Для браузерных
запросов с credentials CORS разрешён только для `https://cad.ya-erm.ru`;
не применять `Access-Control-Allow-Origin: *`. Параметры OAuth callback
проверяются через state и связь с браузером, а не по заголовку Origin.
Пользовательские сессии не заменяются IAM-токеном сервисного аккаунта функции.

Согласованные настройки в `auth-policy.mjs`: попытка входа — 10 минут,
сессия — 180 дней с продлением при активности не чаще раза в сутки.
Продление реализовано обработчиком сессий, а не механизмом TTL.
Роль `lockbox.payloadViewer` назначена `webcad-api` только на `webcad-oauth`.
Аккаунт шлюза не имеет доступа к секрету.
В `auth_sessions` и `auth_requests` включён TTL по `expires_at`:
фоновое удаление не заменяет проверку срока действия в приложении.

Для первой версии нет необходимости сохранять токены Яндекса после получения
профиля: доступ к другим API Яндекса не нужен. Логи не должны содержать code,
state, cookies, токены, PKCE verifier или Client Secret.

## Проверки

- Корректный вход и отказ пользователя в согласии.
- Подмена state, неверная браузерная cookie, истёкший и повторный callback.
- Сбой токен-эндпоинта/профиля Яндекса и временный сбой YDB.
- Одновременный первый вход одного пользователя без создания двух аккаунтов.
- Истечение и отзыв сессии, CSRF, разрешённый и посторонний Origin.
- Офлайн-редактор продолжает работать без входа и без сети.

Источники:
[регистрация приложения](https://yandex.ru/dev/id/doc/ru/register-client),
[Authorization Code, state и PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url).

26 тестов обработчика и OAuth-транспорта, интеграционные проверки настоящей YDB
(включая конкурентный первый вход и потребление попытки) пройдены. На публичном
HTTPS проверены CORS, CSRF, начало входа, отказ и запрет повторного callback.
Интерфейс проверен в браузере с имитацией API, включая работу без сети.
Полный вход с личным подтверждением на странице Яндекса требует проверки пользователем.
